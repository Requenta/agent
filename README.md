# Requenta supplier agent

Connect selected GPU nodes to your Requenta supplier account with Helm. The agent reports node identity, allocatable GPU counts and readiness; it does not provision customer workloads or certify available capacity.

Create a capacity declaration in your console, open Connection & setup, and generate a connection credential. Store that credential as the `token` key in a Kubernetes Secret named `requenta-connection` in the `requenta-system` namespace. Then use the Helm command generated by the console.

```sh
helm repo add requenta https://requenta.github.io/agent
helm repo update
helm upgrade --install requenta requenta/requenta-agent \
  --namespace requenta-system --create-namespace \
  --set-string connection.origin=https://YOUR_CONSOLE_HOST \
  --set-string connection.existingSecret=requenta-connection \
  --set-string nodes.selector=nvidia.com/gpu.present=true
```

Published chart versions pin the multi-architecture image by digest. Helm detects the Kubernetes API endpoints during installation; for offline rendering or a custom CNI, set `networkPolicy.apiServerCIDRs` and the actual API endpoint port explicitly.

## Permissions

The agent lists explicitly selected nodes, reads only the identity of the kube-system namespace when reporting is enabled, and patches only its own status ConfigMap. It runs as a non-root user, with a read-only root filesystem, no host mounts and no workload provisioning permission. Kubernetes and console credentials are separate; redirects are not followed.

Connection mode permits cluster DNS and outbound HTTPS in addition to the Kubernetes API. HTTPS egress is not restricted to a particular destination IP: apply a provider-specific egress policy if required. Inventory-only mode does not enable that egress.

## Operation

Reports are sent every minute. An installation is bound to its first reported cluster UID. Connection credentials expire after 90 days and can be rotated or revoked in the console. An allocatable GPU count does not establish idle or commercially available capacity. Supplier qualification is a separate process.

Uninstall with `helm uninstall requenta -n requenta-system`, then delete the `requenta-connection` Secret. This does not cancel any accepted compute booking.

## Development

Run `go test ./...` and render the chart before publishing. Releases run tests, build linux/amd64 and linux/arm64 images with SBOM/provenance metadata, package a digest-pinned chart and update the Helm repository. This repository contains only the supplier agent and chart; the Requenta platform is maintained separately.
